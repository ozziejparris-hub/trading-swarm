## FOUR REUSABLE LESSONS (record them)

**Simulate a guard against the real data ordering before trusting it.** The
unswept slug fetch's population contains 3,396 zero-padded synthetic ids
(7.76 %) that Gamma cannot resolve. They are not spread through the run —
**3,372 of them sit in the first keyset decile**, because they share a low
`0x03…` prefix and the run is ordered by `market_id`. The fetch's cumulative
`not_found` abort guard (fires above 10 %) would therefore have tripped at
**batch ~2** — spiking to ~46 %, then ~95 % by batch 30 — and exited ABORTED
with the message "identifier assumption likely wrong", which is the *opposite*
of the truth. Nothing in the code was wrong; the interaction between a correct
threshold and the actual key distribution was. Reading the code would not have
found it. Simulating the guard's arithmetic against the real, sorted id list
did, before launch — and the fix (pre-stage the synthetics as a-priori
`not_found` with distinguishable provenance) corrected the *population the
guard measures* rather than raising the threshold.

**A parameter's meaning is an empirical question.** `gamma_batch()` hardcodes
`closed=true`. It was inherited as correct because it worked for the swept
population (already-resolved markets). It is structurally wrong for the
unswept population, which is *defined* as `resolved=0 OR NULL` — mostly still
open on Gamma. Found not by reading the code but by re-querying the first
batch's 83 `not_found` ids **without** the parameter: all 83 exist on Gamma
right now, with real slugs, `closed=False`. Then the parameter itself was
probed — all three forms against a controlled open+closed pair — establishing
that `closed` is a strict binary filter with no "both" value and omitting it
behaves as `closed=false`. That turned "the two-pass merge is safer" into
"the two-pass merge is **necessary**" — a different claim with a different
justification. The probe took minutes.

**Draw the gate before the thing it gates exists, and make the order
provable.** The validation-gate sample sets were committed (`26cb147`) with
**no labels in the tree**; the labels landed in the next commit. Git history
is now the evidence that the 500 rows and the §3.10 rubric were fixed before
any classifier output could shape them. A gate drawn afterwards can always be
doubted; this one cannot. The same discipline applied one level down: the
pre-filter's token lists were drafted entirely from committed docs with
**zero market_ids inspected**, and the coverage script — which does read every
title — was run *once*, after the lists were frozen, and prints aggregate
counts only.

**Record what a mechanism cannot see, not only what it found.** M6 —
`monitor.py`'s Mistral KEEP/EXCLUDE gate — was recorded as "LIVE (hybrid
mode)" in the inventory, inferred from a module constant. It **has never run
in production**: the live entrypoint constructs the monitor with
`ai_agent=None`, so the guard fails and `_ai_categorization_check` is never
called — zero `[AI PATH]` lines across three months of retained journald.
There was no discarded intelligence to recover because none was ever computed.
The honest note ("this was never verified against the entrypoint") was worth
more than the inventory row it corrected. Same shape in the pre-filter's
verified-not-assumed zero-inspection claim, and in the gate's blind
spot-check flagging *its own* composition weakness — a pure-random 50 drew 0
of the 6 Relevant rows, so it calibrates the NotRelevant mass but not the
discriminating calls, and that limitation is written into the artifact by the
system that drew it.
