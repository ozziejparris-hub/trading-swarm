# Relevance-Classifier Validation Gate — Sample Sets Drawn & Labelled

**Date:** 2026-09-01. **Design:** `2026-08-31-relevance-classifier-design.md`
(e601648) §3.9 (the three sample sets) and §3.10 (the labelling rubric).
**Type:** read-only against production; writes only the committed artifacts
under `brain/decisions/gate-sets-2026-09-01/`. **Tagging:** `[V]` verified
this session.

**Why now, before the LLM stage exists:** the classifier's LLM stage is not
built. Drawing and labelling the held-out gate now makes it structurally
impossible to tune the classifier against it, even inadvertently. Once the
LLM exists this property is gone. Nothing in this task builds, prompts, or
runs any classifier; no `category` / `category_source` /
`category_classification_log` row is written.

## PART 1 — THE DRAW

### Seed & procedure `[V]`

- **`GATE_SEED = 20260901`**, `random.Random(20260901)`.
- Frame rows sorted by `market_id`. `rng.sample(range(len(frame)),
  len(frame))` produces one deterministic consumption order per frame; the
  draw walks that order, skips any contaminated pick (below), and takes the
  first **350** clean rows from the EXCLUDE frame and the first **150** clean
  rows from the RESIDUAL frame.
- **EXCLUDE split:** `sample[:200] → set_c`, `sample[200:350] → set_a`.
  `set_a` and `set_c` are therefore **disjoint by construction** — a
  deliberate strengthening over §3.9 (which describes them as independent
  draws); it removes any "same market scored in two metrics" objection.
- `set_b` is drawn from the RESIDUAL frame after `set_a`/`set_c`; disjoint
  from both (different frame). All three pairwise-disjoint, asserted in code.

### Frames `[V]`

| frame | definition | size |
|---|---|---:|
| Unknown population | `markets.category = 'Unknown'`, non-empty title | 778,982 |
| **EXCLUDE** (`set_a`, `set_c`) | above ∧ `relevance_prefilter.prefilter(title) == 'EXCLUDE'` | **634,715** |
| **RESIDUAL ∧ no-keyword** (`set_b`) | above ∧ `prefilter(title) == 'RESIDUAL'` ∧ no M9 keyword | **125,208** |

**"No election/geopolitics token"** (§3.9's phrase for the `set_b` frame) is
operationalised as **M9's `KEYWORD_FILTER`** — the 39-token positive list in
`scripts/backfill_market_categories.py`, matched with M9's own semantics
(`LOWER(title) LIKE '%kw%'`, bare substring). `relevance_prefilter.py`
deliberately carries no positive list, so M9's is the canonical
"election/geopolitics token" set the design refers to (design §1.3). The
list is recorded verbatim in `manifest.json`. Substring semantics are
deliberately kept (not word-boundary) — they only *widen* what `set_b`
excludes, keeping `set_b` strictly the genuinely-ambiguous middle.

`set_b` staged-slug coverage: **62 / 150** have `market_slug` / `event_slug`
/ `event_title` from `relevance_slug_staging` (the swept + unswept residual
slug fetches); the other 88 are title-only. Per §3.10 slugs are used "where
available"; missing slugs push a labelling call toward `borderline →
NotRelevant`, which is the intended conservative default.

### Contamination check (mandatory) `[V]`

`2026-08-31-prefilter-implementation.md` records that **zero `market_id`s
were inspected** while drafting the pre-filter token lists — every pattern
traces to a committed doc or the task prompt, and
`measure_prefilter_coverage.py` prints "aggregate counts only — never a
title". This check verifies that claim holds for the drawn 500.

- **Corpus:** 15 files — the 6 provenance-cited decision docs
  ([D1]–[D4] + the record doc), 5 adjacent classifier docs, and the
  pre-filter module + its test + its coverage script + `detect_insider_activity.py`
  (the [D3] `_EXCLUSION_KEYWORDS` source). 315,475 chars; **1** `0x…64hex`
  id present in the whole corpus. (Over-inclusive on purpose — a wider
  corpus can only reject more.)
- **Test, per drawn row:** `market_id` ∈ corpus's `0x`-id set; **or** the
  row's `title` (≥ 20 chars) appears verbatim as a substring; **or** a
  staged `market_slug` / `event_slug` / `event_title` (≥ 15 chars) appears
  verbatim. Case-insensitive. A contaminated pick is dropped and replaced by
  the next clean pick from the same stream.
- **Result: 4 picks excluded, all from the EXCLUDE frame, all the generic
  template title `"Games Total: O/U 2.5"`** — quoted as a skip-sample row in
  `2026-08-30-category-classifier-investigation.md`. These are template
  *instances* (hundreds of distinct markets share that exact title; none was
  individually inspected), but the rule is applied literally: excluded,
  redrawn, and recorded in `manifest.json → contamination_check.exclusions`.
  **Zero exclusions from `set_b`.** No drawn `market_id` appeared anywhere in
  the corpus.

## PART 2 — LABELS

Written **after** the sets were committed (commit `26cb147`). Each of the 500
rows carries `market_id, title, market_slug, event_slug, event_title, label,
subtype, borderline, reason` in `gate-sets-2026-09-01/labels.csv`. Labels
applied against the **§3.10 rubric verbatim** — Elections / Geopolitics /
NotRelevant, `Relevant = Elections ∨ Geopolitics`; evidence = title + staged
slugs only, nothing else; genuinely-unsure → `NotRelevant` + `borderline`;
ties break conservatively.

### Distribution `[V]`

| set | n | NotRelevant | Relevant | of which Elections / Geopolitics | borderline (all labelled NotRelevant) |
|---|---:|---:|---:|---:|---:|
| **a** — template bucket | 150 | **150** | **0** | 0 / 0 | 0 |
| **b** — ambiguous residual | 150 | **144** | **6** | 4 / 2 | 4 |
| **c** — pre-filter exclusions | 200 | **200** | **0** | 0 / 0 | 0 |
| **total** | 500 | **494** | **6** | 4 / 2 | 4 |

### What each distribution means for the gate

- **set_a → 0 / 150 Relevant.** Every one is a crypto up/down, crypto price
  level, weather, sports line/prop/spread/match, esports, stock, or
  entertainment-award market. When the classifier runs, **any `Relevant`
  call on a set_a row is a false positive**; §3.9 allows ≤ 2 % (≤ 3).
- **set_c → 0 / 200 Relevant.** None of the 200 markets the deterministic
  pre-filter EXCLUDES is actually Geo/Elec on hand-inspection. This is the
  §3.9 pre-filter-false-exclusion measurement (threshold ≤ 0.5 %, ≤ 1 of
  200); the hand-label result is **0 of 200** — i.e. in this sample the
  pre-filter discards nothing relevant. (The formal gate number is computed
  once, later, with the classifier in the loop; this is the hand-label side
  of it, fixed now.)
- **set_b → 6 / 150 Relevant** (4 % genuine-positive base rate in the
  "genuinely ambiguous zone"). The 6:
  1. *Will Joshua Vasquez be the Republican nominee for FL-06?* — Elections
     (nomination/primary; slug `fl-06-republican-primary-winner`).
  2. *Will a candidate win outright in Ireland's first round?* — Elections
     (electoral-round outcome).
  3. *Will Pelosi say "Stocks" at DNC speech?* — Elections (declared political
     figure, say-prop scoped to a political event — §3.10's explicit clause).
  4. *Will Bill Clinton say "Hillary" at DNC speech?* — Elections (same
     clause).
  5. *Will the US strike Yemen next?* — Geopolitics (armed state action; slug
     `next-country-us-strikes`).
  6. *Will Israel strike ≥ 4 countries in April 2026?* — Geopolitics (armed
     state action).
  The classifier's FP rate on set_b's 144 NotRelevant rows must be ≤ 10 %
  (≤ 15) per §3.9.
- **4 borderline, all conservatively NotRelevant**, all in set_b:
  *reconciliation-bill passage* (domestic legislative vote — not an electoral
  vote, not international), *Zohran Mamdani named in Epstein files* (subject
  is an elected official but the resolution basis is a document release, not
  political-capacity conduct), *Judge McConnell impeached* (a legislative
  vote, but a judge is not an electoral figure and impeachment is not in the
  §3.10 lists), *Ted Cruz weekly post-count* (a sitting senator, but a raw
  volume prop, not scoped to a political event). Each is defensible either
  way; the rubric's tie-break rule sends all four to NotRelevant + borderline.
  If the eventual adjudication overturns any, that is visible because the
  `borderline` flag is recorded now.

### Notes on rubric application (fixed, so they can be checked)

- **"will X post/say …" props:** counted Relevant **only** when the subject
  is a declared political figure **and** the market is scoped to a political
  event (Pelosi/Clinton at the DNC). The seven *Elon Musk weekly tweet-count*
  markets and the *Ted Cruz weekly post-count* market are **not** — they are
  volume metrics not tied to a political event; Musk additionally is not an
  office-holder. (Musk ones: plain NotRelevant. Cruz: NotRelevant + borderline,
  because his office gives it a pull the rubric's "scoped to a political
  event" test nonetheless fails.)
- **Nation-named sports** ("United States vs. Belgium: O/U Corners",
  "Will Bulgaria win on 2025-11-15?", "Will Czechia win on 2026-05-31?",
  "Switzerland leading at halftime?") → NotRelevant. National teams in a
  fixture are not state action.
- **Economic data** (unemployment rate, jobs added, TSA passenger counts,
  ETF flows) → NotRelevant. Economics is explicitly outside `Relevant` in
  §3.10.
- **Non-political say-props** (All-In Podcast, Joe Rogan, Michael Saylor
  keynote, S&P Global earnings call, Shayne Coplan on 60 Minutes) →
  NotRelevant — the speaker is not a declared political figure.

## PART 3 — LIMITATION OF THIS GATE (stated plainly)

**The labels in `labels.csv` were produced by the same system (this Claude
Code session) that will build and run the classifier being gated.** A gate
labelled by the mechanism under test is weaker than one labelled by a fully
independent party: a blind spot in how this system reads a market title —
e.g. the "scoped to a political event" test above, or the nation-named-sports
call — will be shared by the labels *and* by the classifier, so the gate
cannot catch it. This is a real weakness and is not mitigated away by
anything below.

**What does hold, and limits the damage:**

1. **Drawn and frozen before the LLM stage exists.** No prompt, no
   classifier, no run — nothing to tune the sets or labels toward. Git
   history (`26cb147` sets-only, then labels) is the evidence.
2. **Rubric fixed in advance** — §3.10 of a design doc committed
   2026-08-31 (e601648), quoted verbatim here, applied without
   reinterpretation.
3. **Ties break conservatively** — every genuinely-unsure call is
   NotRelevant + `borderline`, recorded, so an over-generous classifier
   cannot hide behind an over-generous label.
4. **Contamination check passed** — the drawn 500 do not appear in the
   pre-filter's drafting artifacts (4 generic-template-title picks excluded
   and redrawn; details in `manifest.json`).
5. **The blind spot-check below** — an independent reviewer (Oscar) relabels
   a random 50 without seeing the model labels; the agreement rate is
   recorded as a measured property of the gate, giving one external
   calibration point on the label quality.

None of 1–5 makes the labeller independent. They bound, not remove, the
weakness; a reader of the eventual gate-result doc should weigh the outcome
with this in mind.

## PART 4 — BLIND SPOT-CHECK

- **File:** `gate-sets-2026-09-01/spotcheck_blind.csv` — 50 rows:
  `row, set, market_id, title, market_slug, event_slug, event_title` plus
  **empty** `oscar_label`, `oscar_borderline`, `oscar_note` columns. **No
  model label, subtype, borderline flag, or reason is present in this file.**
- **Seed:** `SPOTCHECK_SEED = 90150`, `random.Random(90150).sample(range(500),
  50)` over `labels.csv` row order, then sorted. Recorded in
  `spotcheck_meta.json`. `sha256/16(spotcheck_blind.csv) = b11a49101638b00e`.
- **Composition of the 50** (consequence of a pure-random draw, reported not
  engineered): **15 from set_a, 17 from set_c, 18 from set_b**; by model
  label **50 NotRelevant, 0 Relevant**, 2 of the 4 borderline rows included.
- **Procedure for Oscar:** label each row Relevant / NotRelevant (and
  Elections / Geopolitics if Relevant) against §3.10, using only the title
  and the slugs in the file; mark `oscar_borderline = 1` where unsure. Do not
  open `labels.csv` or this doc's Part 2 first. Agreement is then a join on
  `market_id` between the filled `spotcheck_blind.csv` and `labels.csv`, and
  the % agreement (plus any disagreement list) is recorded as a property of
  the gate.
- **Known weakness of this sample:** a pure-random 50 of 500 drew **0 of the
  6 Relevant rows** and only 2 of 4 borderline, so it calibrates agreement on
  the NotRelevant mass (≈ 99 % of the gate) but does **not** directly test
  agreement on the discriminating positive calls. A worthwhile supplement —
  Oscar's call, not baked into the blind file so the "random 50" stays
  exactly that — is a second independent pass over the 6 Relevant + 4
  borderline set_b rows by `market_id`.
